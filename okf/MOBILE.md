# Mobile app (mobile/, package `deskctrl`, Android only, Flutter 3 / Dart 3.13)

Display name: **ViL** (Android label and MaterialApp title). Owner-approved binary bow icon: `branding/vil-icon.png`; the master and generated launcher layers have a transparent outside background. Legacy mipmap PNGs and adaptive launcher foreground/background are generated by `tools/prepare_branding.py`. Package ID and saved data stay compatible with DeskCtrl.

Deps: web_socket_channel, sensors_plus, wakelock_plus, shared_preferences, audioplayers, mobile_scanner. Landscape locked by default; Mouse and Mobile screens can use portrait.

## Conventions
- Colours: `context.desk.{bg,key,keyAlt,keyMod,pad,padActive,padOff,body,accent,accentDim}` - never hard-code new surface colours.
- Computer identity colours come from `deviceColor(id)`; transport status keeps its own green/orange/red colour.
- Settings change = `Settings.instance.update(() => s.field = v)` (persists + notifies). New field -> `SETTINGS.md`.
- Raw `Listener` for multi-touch (pad, menu); `HitTestBehavior.opaque` for overlays so touches do not leak.
- Custom menu keys: `CustomKey` (custom_key.dart), looked up through `editActionFor(id)` (built-in catalog first, then `Settings.editCustom`); layout ids are `custom_<n>`.
- Edit menu options live in `editCatalog` (id -> EditAction); add a new option there, and the editor lists it. Layout saved as `Settings.editLayout`.
- Overlays (edit menu) are `OverlayEntry`, closed through one `_close()`; no route/Navigator for them.
- `SwitchGuard.touch()` is called by the Alt/Ctrl+Tab slider; auto-keyboard waits 700 ms while it is active.
- Test seams: `Link.deadAfter`, `Connection.lastClickAt`, `SwitchGuard.reset`.

## Kotlin (`MainActivity.kt`)
Channels: `deskctrl/bt` + `deskctrl/bt/events` (RFCOMM per address), `deskctrl/window` (`setCutout`, `setBrightness`),
`deskctrl/phone_media` (`action`, `volume`, `mute`, `brightness`: Android media keys/audio stream/window brightness),
`deskctrl/remote_audio` (`start`, `write`, `gain`, `stop`: bounded 48 kHz PCM playback in `RemoteAudio.kt`),
`deskctrl/link` + `/events` (deep link `deskctrl://pair/...`, initial + `onNewIntent`). Manifest: INTERNET, CAMERA, BLUETOOTH perms,
VIEW intent filter for `deskctrl://pair`, `launchMode=singleTop`.

`RemoteAudio.kt` requests Android media audio focus, creates a streaming PCM16 `AudioTrack` on the current Android media route, and uses a 4-frame Low or 6-frame Balanced queue. A full queue drops the oldest frame to limit latency. It preloads 40 ms (Low) or 60 ms (Balanced) before play, requests low-latency performance, uses audio thread priority, and preserves partial AudioTrack writes through `PcmPump.kt`. Stop interrupts the worker, clears memory, flushes/releases the track, and abandons focus. No audio is written to storage.

## Now-playing trackpad badge
`now_playing.dart` defines `NowPlaying` (title, app, playing, PNG bytes), `NowPlayingBadge`, and a clipped automatic marquee. `links.dart` reassembles bounded `0x16` JSON chunks independently per transport; `Session.nowPlaying` holds each computer's report. The Trackpad listens to Connection and shows the active live computer's app icon and title below the volume marks within exactly 40dp. Long titles pause 1.2 seconds then scroll at 18dp/s; short titles stay centered and reduced-motion disables animation. The icon is 16dp and the title 10sp. Compact combined Mobile layouts reserve space below the scaled volume marks; extremely short pads omit the badge. It is display-only and does not intercept trackpad gestures. Desktop metadata is hidden when Phone media mode is selected, and no live link means no stale badge. Known playback state also drives the top play/pause icon.
