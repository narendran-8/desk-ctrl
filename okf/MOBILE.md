# Mobile app (mobile/, package `deskctrl`, Android only, Flutter 3 / Dart 3.13)

Display name: **ViL** (Android label and MaterialApp title). Owner-approved binary bow icon: `branding/vil-icon.png`; the master and generated launcher layers have a transparent outside background. Legacy mipmap PNGs and adaptive launcher foreground/background are generated by `tools/prepare_branding.py`. Package ID and saved data stay compatible with DeskCtrl.

Deps: web_socket_channel, sensors_plus, wakelock_plus, shared_preferences, audioplayers, mobile_scanner. Landscape locked by default; Mouse and Mobile screens can use portrait.

## Conventions
- Colours: `context.desk.{bg,key,keyAlt,keyMod,pad,padActive,padOff,body,accent,accentDim}` - never hard-code new surface colours.
- Computer identity colours come from `deviceColor(id)`; transport status keeps its own green/orange/red colour.
- Settings change = `Settings.instance.update(() => s.field = v)` (persists + notifies). New field -> `SETTINGS.md`.
- Raw `Listener` for multi-touch (pad, menu); `HitTestBehavior.opaque` for overlays so touches do not leak.
- Custom menu keys: `CustomKey` (custom_key.dart), looked up through `editActionFor(id)` (built-in catalog first, then `Settings.editCustom`); layout ids are `custom_<n>`.
- Edit menu options live in `editCatalog` (id -> EditAction); add a new option there, and the editor lists it. Layout saved as `Settings.editLayout`.
- Overlays (edit menu) are `OverlayEntry`, closed through one `_close()`; no route/Navigator for them.
- `SwitchGuard.touch()` is called by the Alt/Ctrl+Tab slider; auto-keyboard waits 700 ms while it is active.
- Test seams: `Link.deadAfter`, `Connection.lastClickAt`, `SwitchGuard.reset`.

## Kotlin (`MainActivity.kt`)
Channels: `deskctrl/bt` + `deskctrl/bt/events` (RFCOMM per address), `deskctrl/window` (`setCutout`, `setBrightness`),
`deskctrl/phone_media` (`action`, `volume`, `mute`, `brightness`: Android media keys/audio stream/window brightness),
`deskctrl/remote_audio` (`start`, `write`, `gain`, `stop`: bounded 48 kHz PCM playback in `RemoteAudio.kt`),
`deskctrl/link` + `/events` (deep link `deskctrl://pair/...`, initial + `onNewIntent`). Manifest: INTERNET, CAMERA, BLUETOOTH perms,
VIEW intent filter for `deskctrl://pair`, `launchMode=singleTop`.

`RemoteAudio.kt` requests Android media audio focus, creates a streaming PCM16 `AudioTrack` on the current Android media route, and uses a 4-frame Low or 6-frame Balanced queue. A full queue drops the oldest frame to limit latency. It preloads 40 ms (Low) or 60 ms (Balanced) before play, requests low-latency performance, uses audio thread priority, and preserves partial AudioTrack writes through `PcmPump.kt`. Stop interrupts the worker, clears memory, flushes/releases the track, and abandons focus. No audio is written to storage.

## Now-playing trackpad badge
`now_playing.dart` defines `NowPlaying` (title, app, playing, PNG bytes), `NowPlayingBadge`, and a clipped automatic marquee. `links.dart` reassembles bounded `0x16` JSON chunks independently per transport; `Session.nowPlaying` holds each computer's report. The Trackpad listens to Connection and shows the active live computer's app icon and title in a horizontal row directly beneath the playback buttons, within their middle-60% strip. Long titles pause 1.2 seconds then scroll at 18dp/s; short titles center together with the source-app icon and reduced-motion disables animation. The icon is 16dp and the title 12sp. The row is 24dp tall, starts below the 40dp playback strip, and keeps trackpad hints underneath (scaled down on compact pads); pads shorter than 100dp omit the badge. It is display-only and does not intercept trackpad gestures. Desktop metadata is hidden when Phone media mode is selected, and no live link means no stale badge. Known playback state also drives the top play/pause icon.

## Playback timeline
`NowPlaying` also carries positionMs, durationMs, rate, canSeek, seekKey and a local receive timestamp. `MediaTimeline` displays a single row: previous, elapsed, expanded split red/grey seek line with play/pause in its center gap, duration, next. Previous/play/next use existing consumer HID commands; rewind/forward send clamped absolute seeks by 10 seconds. Holding either button begins repeating after the long-press threshold (500ms), then seeks another 10 seconds every 250ms until release. Repeats accumulate from the pending position, clamp to the track boundaries and stop on cancellation, moving more than 18dp outside the button, track change, or loss of seek capability. While playing, a 250ms timer interpolates from the most recent report (capped at 4 seconds without a fresh report), respecting pause/rate and duration. A drag previews the target; releasing sends one absolute seek to the pinned computer and track. A changed track cancels the old drag, and a pending preview expires after five seconds if no matching feedback arrives. Unknown total duration shows --:--. `canStep` requires position, CanSeek and a valid track key; forward/backward remain enabled without duration. Only the percentage timeline requires a positive duration (`seekable`).
The interactive timeline is a sibling above the raw trackpad Listener, starting at y=0, height 64dp, inset by the 40dp edge zones. Its control row is 40dp high and the interactive title row occupies y=40..64. The legacy top marks are hidden when this row is shown. Thus a seek never moves/clicks the remote mouse. It is shown only for pads >=150dp tall with known time metadata; very compact pads hide gesture-help text while the timeline is shown, keeping bottom controls clear. `Connection.seekMedia` validates the active computer, live link, track key and permission before sending. Old agents without timing metadata keep their title-only UI.

Seek-button gesture fix: a single GestureDetector owns tap and hold (no nested IconButton recognizer); accessible semantics remain. An 18dp movement allowance around the narrow 26x40dp hit area prevents natural finger drift from cancelling repeats. Repeated holds survive same-track feedback rebuilds.

Remote Audio recovery: `_AudioSocket` enables 15-second WebSocket pings. A healthy established Wi-Fi/USB endpoint stays pinned when another transport appears. Unexpected source/sink close/error and agent error statuses share the same opt-in recovery path as transport loss; retries use 1/2/4/8-second capped backoff, preserving original source id and selected output even when the input target changes. Generation guards ignore old socket callbacks. Recovery cleanup completes before a manual restart, and Stop cancels pending recovery. The Audio Output panel keeps its body scrollable and reconnect/Stop footer visible in landscape. It exposes the existing auto-reconnect preference and permits Stop while connecting; opening it during recovery does not reset discovery/state. Native focus policy and audio wire format are unchanged.

Timeline metadata continuity: Session passes its previous NowPlaying into parsing. Same-video duration and last position survive transient null/zero duration or null position reports; empty media and player/track/title/URL changes clear the cache. Each computer has its own cache. The timing model includes player, trackId and mediaUrl; timeline gesture identity uses these stable fields (legacy agents fall back to their supplied identity/key). A legacy key rotation for the same identified video updates the in-progress drag key instead of cancelling the drag. Repeat-button state also uses stable video identity. Pending seek preview allows five seconds for source feedback before reverting to the reported position.

Post-seek playback clock: `Connection.seekMedia` seeds the selected Session's NowPlaying clock at the requested target and marks it estimated. Repeated zero, missing, or clearly pre-seek reports do not replace that clock merely because the widget's five-second preview expires. The estimated clock advances with playback rate and honors pause; same-track feedback within 3 seconds of the expected clock confirms it and removes estimation. New tracks/players and disconnect clear it. Approximate elapsed time is prefixed with `~`; this is a fallback while source position feedback disagrees, not a guarantee that the source accepted the seek. Normal authoritative feedback, including seeking to zero, is honored after synchronization returns. No desktop/protocol upgrade is required for this client-side correction.

Split progress control: `split_media_seek_bar.dart` replaces the overlaid Slider with a painted left/right track and a separate 38dp play/pause slot. Both halves map to one timeline (0-50%, 50-100%); the playhead jumps between visible inner endpoints at the midpoint, never behind the button. A shared horizontal drag can cross the gap; center tap only operates play/pause. Accessible increase/decrease actions remain available; disabled/live tracks remain read-only. Existing Session seek-clock behavior is unchanged.

Track title seek controls: the existing backward/forward repeat buttons now flank the app-icon/title row instead of the progress row. A horizontal title swipe of at least 24dp performs exactly one 10-second seek: right forward, left backward. Short touches do nothing. The swipe pins video identity and cancels on track changes; buttons retain tap and hold-repeat behavior. This complete media overlay is outside the raw trackpad Listener, so title gestures cannot move/click the desktop pointer. EdgeZoneMarks suppresses its passive duplicate badge only while the interactive MediaTimeline overlay is present; legacy title-only/very short-pad layouts remain unchanged.
